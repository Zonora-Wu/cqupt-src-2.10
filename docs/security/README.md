# Security

安全设计与检查清单目录。

## 当前安全基线

- `.env`、`.env.*` 不提交。
- `storage/` 和 `tmp/` 不提交真实运行数据。
- 前端校验只作为用户体验，后端必须重新校验。
- Prisma schema 已通过语法验证，但还未连接真实数据库。
- 后端已增加环境变量基础校验。
- 后端已限制 CORS 来源为 `FRONTEND_ORIGIN`。

## 核心安全要求

### 身份认证

- 密码必须哈希存储，不能明文存储。
- 邮箱验证码只保存哈希。
- Access Token 短有效期。
- Refresh Token 保存哈希，并支持撤销。
- 登录、退出、刷新令牌都需要审计。

### 权限控制

- 使用 RBAC + 用户级权限覆盖。
- 用户只能一个角色。
- 审核员证书签发权限由管理员开启。
- 前端显示权限不能作为后端授权依据。

### 授权范围

- 用户授权等级：`BASIC / TRUSTED / STAFF`。
- 资产范围：`PUBLIC / INTERNAL / SPECIAL`。
- 后端根据 `authorization_policies` 判断用户是否可测试对应资产。

### 文件上传

- 只允许 PDF。
- 单文件最大 10MB。
- 后端校验 MIME、扩展名、大小、SHA256。
- 后续接入病毒扫描。
- 敏感附件下载必须鉴权并写审计日志。

### 漏洞报告

- 漏洞提交后不可撤回。
- 状态变更必须写事件表。
- 漏洞复现细节不能公开展示。
- 审核意见和复测记录需要保留。

### 证书查询

- 公开核验只能返回脱敏信息。
- 不能返回漏洞复现步骤、请求包、敏感资产信息。
- 证书撤销后仍保留历史记录。

### AI

- 前端不能直连 Hermes Agent。
- AI 调用必须通过后端 AI Gateway。
- 只保存脱敏输入摘要和输出摘要。
- 原始对话不长期保存。
- AI 对系统的操作必须人工确认。
- AI 调用必须写审计日志。

### 审计日志

必须记录：

- 登录、退出
- 提交漏洞
- 查看敏感附件
- 审核操作
- 漏洞状态变更
- 证书签发/撤销
- 公告发布
- 用户权限变更
- 系统设置变更
- AI 调用

默认保留策略暂定 3 年。
