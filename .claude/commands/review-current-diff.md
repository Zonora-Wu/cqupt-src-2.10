# 当前改动审查

审查当前工作区 diff，重点找出会影响 CQUPT-SRC 生产级开发的问题。

## 必须检查

1. 运行或读取当前 git diff / status。
2. 区分：
   - 本次任务相关改动
   - 之前已经存在的改动
   - 可疑的无关改动
3. 不要审查 `dist`、`node_modules`、`tmp`、`uploads`、`tests/e2e/evidence` 等产物。

## 审查维度

- 正确性：实现是否符合当前需求。
- 架构边界：前端是否绕过后端；Hermes 是否越权；Runner 是否越界。
- 安全性：RBAC、审计日志、敏感数据、SSRF/内网/metadata 拦截是否保持。
- 数据一致性：Prisma schema、migration、TypeScript 类型是否一致。
- 前端体验：卡片/内嵌操作/圆角/布局是否符合项目风格。
- 测试证据：是否运行了真正相关的 build/test/validate。
- 文档同步：是否需要更新 docs。

## 输出格式

按严重程度输出：

```text
阻塞问题
1. [文件:行] 问题 + 为什么阻塞 + 建议修法

需要改进
1. [文件:行] 问题 + 建议

可接受但需说明
1. 说明

验证状态
- 已验证：命令 + 结果
- 未验证：原因
```

不要因为代码能编译就判定完成；没有真实验证输出时要明确写“未验证”。
