# CQUPT-SRC 总体建议

## 当前判断

不建议继续无限打磨前端。当前前端已经覆盖访客、用户、审核员、管理员主要页面，下一阶段应以“后端真实接口 + 数据库 + 权限 + 审计”为主线推进。

推荐路线：

```text
前端原型冻结 v0.1
  -> 数据库模型
  -> 后端基础服务
  -> 认证与 RBAC
  -> 漏洞提交与审核闭环
  -> 文件上传与证书
  -> AI Gateway + Hermes Agent
  -> Docker Compose 本地联调
  -> Ubuntu 云服务器部署
```

## AI 接入建议

Hermes Agent 不应该由前端直接调用，应采用：

```text
前端
  -> 后端 API
  -> AI Gateway
  -> Hermes Agent
```

AI 重点能力：

1. 用户提交漏洞时解析 PDF，提取标题、资产、类型、复现步骤、修复建议。
2. 审核员审核时辅助判断漏洞价值、材料完整度、复测 checklist。
3. 学习中心推荐资源和靶场。
4. 管理员生成运营摘要、资产风险画像和审计分析。

安全要求：

- 不保存原始敏感对话。
- 只保存脱敏摘要、skill 和 FAQ。
- AI 对系统的操作必须人工确认。
- AI 调用必须写审计日志。

## 下一步

现在最应该做：

```text
实现认证与 RBAC 基础模块
```

原因：

- 登录是所有真实接口的入口。
- RBAC 是学生、审核员、管理员权限边界的基础。
- 后续漏洞提交、审核、证书、公告、AI 都依赖当前用户身份和权限。

建议下一步拆成：

1. 初始化角色和权限 seed。
2. 实现密码哈希。
3. 实现统一认证码 + 密码登录。
4. 实现 JWT access token / refresh token。
5. 实现 `GET /api/auth/me`。
6. 实现权限守卫。
7. 前端登录从 mock 切换到真实接口。
