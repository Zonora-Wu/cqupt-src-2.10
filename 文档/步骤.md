4. 用户管理 API

**第一阶段：公告管理 API**

目标：

- 管理员、审核员可以发布公告
- 可以保存草稿、发布、下线
- 公告可面向全体、学生、审核员、管理员
- 访客首页可以查看公开公告
- 登录用户也可以查看平台公告
- 点击公告详情进入详情页
- 公告发布、下线、修改写入审计日志

后端要做：

1. 新建 `announcements` 模块
2. 实现接口：
   - `GET /api/announcements/public`
   - `GET /api/announcements`
   - `GET /api/announcements/:id`
   - `POST /api/announcements`
   - `PATCH /api/announcements/:id`
   - `POST /api/announcements/:id/publish`
   - `POST /api/announcements/:id/offline`
3. 权限控制：
   - 公开公告接口不需要登录
   - 管理接口需要 `announcement:manage`
4. 审计日志：
   - 发布公告：`PUBLISH_ANNOUNCEMENT`
   - 下线公告：也先用 `PUBLISH_ANNOUNCEMENT`，metadata 里区分动作
5. 数据校验：
   - 标题不能为空
   - 内容不能为空
   - 发布范围必须合法
   - 草稿可以内容少一点，发布必须完整

前端要做：

1. 管理员公告管理页接真实接口
2. 审核员公告管理页复用同一套页面
3. 访客公开公告页接真实接口
4. 用户端平台公告页接真实接口
5. 公告详情页接真实接口
6. loading / error / empty 状态补齐

**第二阶段：学习资源 / 靶场资源 API**

目标：

- 合并“工具资源”和“靶场中心”为学习管理
- 前端用户学习中心读取真实数据
- 管理端可以新增、编辑、下线资源
- 下载或访问资源可以统计次数

后端接口：

- `GET /api/learning/public`
- `GET /api/learning`
- `POST /api/learning`
- `PATCH /api/learning/:id`
- `POST /api/learning/:id/offline`
- `POST /api/learning/:id/click`

权限：

- 用户可查看已发布资源
- 管理员、审核员按当前设计可管理则使用 `learning:manage`

**第三阶段：积分商城 API**

目标：

- 商品列表真实化
- 用户可以兑换商品
- 线下领取状态流转
- 管理员可以管理商品和兑换记录

核心接口：

- `GET /api/mall/items`
- `POST /api/mall/items`
- `PATCH /api/mall/items/:id`
- `POST /api/mall/redemptions`
- `GET /api/mall/redemptions/my`
- `GET /api/mall/redemptions`
- `POST /api/mall/redemptions/:id/pickup`
- `POST /api/mall/redemptions/:id/cancel`

重点规则：

- 积分不足不能兑换
- 兑换后写积分流水
- 状态只允许：待领取、已领取、已取消

**第四阶段：用户管理 API**

目标：

- 管理员用户管理页真实化
- 支持禁用 / 启用用户
- 支持修改角色
- 支持开启或关闭审核员证书签发权限
- 支持查看用户责任书、积分、证书、漏洞概览

核心接口：

- `GET /api/users`
- `GET /api/users/:id`
- `PATCH /api/users/:id`
- `POST /api/users/:id/enable`
- `POST /api/users/:id/disable`
- `POST /api/users/:id/permissions`

**第五阶段：审计日志 API**

目标：

- 管理员可以查看关键操作记录
- 支持按用户、动作、时间、对象类型筛选
- 不允许普通用户查看

接口：

- `GET /api/audit-logs`

先做只读即可，后面再做导出。

**第六阶段：证书模板坐标配置**

现在证书已经可以叠加文字和盖章，但坐标还主要靠后端默认 `layoutJson`。

下一步可以在系统设置里做：

- 证书字段坐标配置
- 字号配置
- 印章位置和大小配置
- 预览效果
- 保存后实时影响新签发证书

这个阶段不急，等公告、学习、积分这些业务 API 先接完更稳。

**第七阶段：AI Gateway + HermesAgent**

等基础业务 API 稳定后再接 AI，因为 AI 需要调用真实业务能力。

建议先做三个 AI 能力：

1. 漏洞报告 AI 提交  
   上传 PDF 或输入文本，AI 帮用户生成标题、资产、类型、复现步骤、修复建议。

2. 审核员 AI 辅助  
   AI 给出漏洞价值预判、材料完整度检查、是否建议补充材料。

3. 学习路线 AI  
   根据用户漏洞提交情况、学习资源、靶场资源推荐学习路径。

AI 原则：

- 前端不能直接调用 HermesAgent
- 所有 AI 请求走后端
- 原始对话不长期保存
- 只保存脱敏摘要、FAQ、skill
- AI 产生的系统操作必须人工确认
